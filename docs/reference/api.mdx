Admin endpoints need `Authorization: Bearer <api key>`. Agent endpoints accept an agent key or token.

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/v1/decide` | Get a verdict for an action |
| GET | `/v1/health`, `/v1/version` | Liveness, version and edition |
| GET | `/metrics` | Prometheus metrics |
| GET | `/v1/events`, `/v1/events/stream` | Recent events, live stream (SSE) |
| POST | `/v1/events/{id}/feedback`, `/v1/feedback` | Mark a decision correct, false positive or false negative |
| GET | `/v1/feedback` | List feedback with label counts; `?include=decisions` attaches the original decision |
| GET | `/v1/audit`, `/v1/audit/verify` | Audit records, chain verification |
| GET, POST | `/v1/agents` | List, register |
| GET, DELETE | `/v1/agents/{id}` | Read, remove |
| POST | `/v1/agents/{id}/token` | Issue an agent token |
| PUT | `/v1/agents/{id}/mode` | Set autonomy mode |
| POST | `/v1/contain`, `/v1/release` | Contain or release an agent |
| GET | `/v1/containments` | Current containments |
| GET | `/v1/approvals`, `/v1/approvals/{id}` | Pending approvals |
| POST | `/v1/approvals/{id}/approve`, `/deny` | Resolve an approval |
| GET | `/v1/incidents`, `/v1/incidents/{id}` | Incidents |
| POST | `/v1/incidents/{id}/resolve` | Resolve an incident |
| GET | `/v1/pins` | Pinned MCP tools |

| POST | `/v1/policies/validate` | Validate policy |
| POST | `/v1/manifests/validate`, `/v1/manifests/compile` | Validate or compile a manifest |
| GET | `/v1/stats` | Summary numbers |
| POST | `/v1/restore` | Restore redacted values |
| ANY | `/llm/openai/v1`, `/llm/anthropic` | LLM proxy |
| ANY | `/mcp/{server}` | MCP proxy |

## Feedback

Tell Rungated when a decision was right or wrong. Feedback is stored as an event, so it is part of the audit trail. With your consent it is the data used to tune thresholds and retrain the detection models.

```bash
curl -X POST localhost:8080/v1/feedback \
  -H "Authorization: Bearer $RUNGATED_API_KEY" \
  -d '{"action_id":"act_123","label":"false_positive","expected":"allow","note":"internal security doc"}'
```

`label` is `correct`, `false_positive` or `false_negative`. `expected` is optional and is the verdict you wanted. Use `event_id` instead of `action_id` when you have the event. Requires a key that can approve.

From the SDKs: `rg.feedback("false_positive", action_id=d.action_id, expected="allow")` in Python, `rg.feedback("false_positive", { actionId: d.actionId }, { expected: "allow" })` in TypeScript.
